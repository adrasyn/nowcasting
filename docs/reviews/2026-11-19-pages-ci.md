# Build once; keep routine data publishing small

This change only alters CI, its browser harness and verification tools. It does
not alter the website, datasets, model/scraper code, weekly schedules, credentials
or GitHub permissions. The two model workflows retain their existing explicit
`gh workflow run deploy.yml --ref main` calls: bot data commits do not reliably
start another workflow through a push event alone.
The v3 caller still treats dispatch acceptance as publication; changing that
caller behaviour is explicitly outside this patch.

## Coverage policy

| Candidate | Browser coverage | Publication |
| --- | --- | --- |
| Any PR targeting main | Six Chromium smoke checks plus all existing 42 Chromium / 15 iPhone WebKit cases | Never |
| Main push or default/weekly dispatch, only allowlisted data/docs differ from published code | Six Chromium smoke checks | Main only |
| Main push/dispatch with unpublished code, dependencies, workflow or unknown paths | Smoke plus full Chromium and WebKit | Main only |
| Manual `verification=full` | Smoke plus full Chromium and WebKit | Main only |
| Manual dispatch on another branch/tag | Smoke plus full Chromium and WebKit | Never |
| Missing/unreachable/unrecognised/divergent published baseline | Full coverage | Main only |

There is no manual “force smoke” switch. Auto compares the complete tree diff
from the fresh public build marker to this candidate, requires that marker to
be an ancestor, and disables rename detection so moving code into a data path
cannot conceal its deletion. Comparing only the last push would miss an earlier
unpublished code commit. A stale baseline only adds checks. The existing public
build is the initial trusted baseline; subsequent code-changing publications
must pass full QA before advancing it. PRs always receive full coverage.

All candidates retain the 75 unit/data/presenter/rollover guards, six simple
generator tests, ten ANZ guards and the CI policy/integrity tests. No source
observations or model runs are made just to benchmark data-only publication.

## Export provenance

1. The candidate job tests units once and builds its own `GITHUB_SHA` once.
2. A manifest records commit, run ID and every export/QA-fixture file hash.
3. The six smoke cases serve that prebuilt export; a second hash check confirms
   it stayed unchanged. CI prebuilt mode cannot silently use a public server.
4. One immutable artifact from this workflow run carries `out/` and separately
   named test fixtures. The fixtures are never inside the published directory.
   Downstream jobs use its emitted immutable ID, not a reusable name. Rerunning
   failed jobs reuses the successful candidate; rerunning all jobs creates a
   new attempt-specific artifact and retests it.
5. Full Chromium and WebKit jobs download and verify that same artifact, run
   independently with one worker each, and verify it again. They do not rebuild
   or rerun units. Portable fixture paths support the container's different cwd.
6. The always-running `deploy` check explicitly rejects failed/cancelled/missing
   candidates and skipped browser jobs when full coverage was required. It
   keeps the prior check name; skipped jobs alone are never proof of required QA.
7. Main publication downloads this run's candidate, checks its identity and
   complete inventory, then uploads that directory to Pages. No rebuild occurs.
8. The quick live check retains the existing routes/assets/GIF/data checks and
   compares every fetched response with the candidate's byte fingerprint. A
   stale or different build under the same commit marker cannot pass.

A PR merge SHA/head and a production squash SHA may differ. Production always
builds and smoke-tests its own output; this workflow makes no claim that a PR
artifact is the production build. This also covers direct main code pushes.

Auto planning fetches commit/tree history without historical blobs for its
ancestor/diff checks. PRs only need their candidate checkout because full
coverage is unconditional there.

WebKit uses the official `mcr.microsoft.com/playwright:v1.59.1-noble` image,
matching the lockfile and checked at runtime, so its OS/browser dependencies are
preinstalled. A lockfile upgrade without a matching image fails closed.
Chromium-only routine jobs avoid the large WebKit OS dependency installation.
See [Playwright CI guidance](https://playwright.dev/docs/ci) and
[workflow artifacts](https://docs.github.com/en/actions/tutorials/store-and-share-data).

## Triggers, concurrency and controls

Push paths include the new CI helpers and shared browser action. PR checks run
for every main-targeted PR, including drafts. Default manual/automated dispatch
uses the same auto policy; explicit full verification remains available. PR
superseded runs may be cancelled, but main publishing runs remain serialized
and are never cancelled in progress. Verification on other refs cannot publish
or block the main concurrency group. The model workflow concurrency is unchanged.

The permitted branch summary reported `protected=false`, with no required
contexts. The detailed protection API returned 403 for the connected
integration. No protection, token or permission settings were changed; the
existing `contents: read`, `pages: write`, `id-token: write` block is retained.

## Measurements and validation

The successful 16 November baseline run
[43779054361](https://github.com/adrasyn/nowcasting/actions/runs/43779054361)
took 2m12s workflow elapsed (2m07s job elapsed). The prior complete production run
[44493353866](https://github.com/adrasyn/nowcasting/actions/runs/44493353866)
took 7m08s workflow elapsed (7m05s job elapsed): 57 browser cases, 18 repeated
public chart cases, and duplicate unit/build work. Browser dependency setup
also varied substantially between runs, including a recorded 12m25s install.

The PR and production run summaries/logs provide the new actual timings and
coverage plan. Benchmark the auto path after the first successful full main
publication using an unchanged main dispatch, which is the same actor-agnostic
entry point used by both weekly workflows. Test data-only diffs, failed coverage,
non-main/manual modes, stale baselines and artifact mismatches in isolated
fixtures; do not manufacture a production observation or run a model for timing.
Runner queues, npm/image downloads and network conditions still vary. A new
code candidate or unavailable baseline deliberately pays for full QA.

Rollback is a normal tested revert of this CI-only change. No data rollback or
model rerun is needed. Do not change repository permissions to make a check pass.
